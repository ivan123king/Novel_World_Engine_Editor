# 功能模块

## 项目管理

最低行为要求：

- 创建小说项目目录
- 打开已有小说项目目录
- 校验必需文件和文件夹
- 安全地创建缺失文件夹
- 显示项目标题和当前章节

## 人物管理

UI 方向：

- 左侧列表：人物名称，支持搜索和筛选
- 右侧 Inspector：基础字段、当前状态、自定义属性、关系、历史
- 支持新增、编辑、删除、复制、归档
- 支持作者新增自定义属性，例如“身体情况”“修为”“心理状态”“秘密身份”

不要只把人物数据当作普通表格行。人物管理的重点是“当前状态 + 历史变化 + 作者自定义设定”。

人物 Inspector 不能只是一组写死字段。它至少应包含：

- 基础信息区：`name`、`identity`、`age`、`traits` 等常用字段
- 当前状态区：`status`，允许动态增加状态项
- 自定义属性区：`customFields`，key 由作者输入，value 支持常见 JSON 类型
- 历史区：展示由事件或手动记录产生的变化

实现时要保留未知字段。即使当前 UI 暂时不展示某些字段，读取后再保存也不能把它们删掉。

## 物品管理

需要记录：

- 名称
- 类型
- 持有人
- 所在地点
- 当前状态
- 来源事件
- 历史记录
- 作者自定义属性

物品会影响剧情连续性，因此归属和位置很重要。物品也不应被固定字段锁死，例如法宝、药物、枪械、信物需要的属性可能完全不同。

## 地点管理

需要记录：

- 名称
- 类型
- 上级地点
- 描述
- 当前控制的势力或人物
- 重要事件
- 作者自定义属性

地点字段也应开放，例如玄幻小说可能需要“灵气浓度”，历史小说可能需要“驻军数量”，科幻小说可能需要“重力环境”。

## 人物关系图

图节点可以是：

- 人物、势力或重要实体

图边需要包含：

- `from`
- `to`
- type
- score
- reason
- history

点击关系边时，应打开 Inspector，显示关系类型、强度、原因和变化记录。

关系 JSON 格式不能依赖具体图渲染库。换图库时，底层数据仍然应该可用。

关系也应支持扩展字段，例如“表面关系”“真实关系”“是否公开”“共同秘密”。

## 剧情事件

事件记录的是故事世界中发生了什么：

- 标题
- 章节或时间
- 参与人物
- 地点
- 结果
- 影响

事件不等于章节正文。事件是从章节中提取或为章节规划的结构化事实。

事件影响不要被固定成少数几种枚举。它应该能描述对人物状态、自定义属性、关系强度、物品归属、地点状态等多类数据的影响。

## 时间线

时间线应该帮助回答：

- 在此之前发生了什么？
- 哪一章改变了这个状态？
- 还有哪些剧情线没有收束？

## 世界状态

世界状态是“当前真实情况”的紧凑快照：

- 当前章节
- 政治状态
- 活跃冲突
- 未完成剧情线
- 全局事实
- 作者按题材需要增加的自定义世界属性

使用事件来解释世界状态为什么发生变化。
