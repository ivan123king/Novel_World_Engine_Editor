# 主工作台页面设计说明

## 目标

这份文档用于指导后续 AI 实现 Novel World Engine Editor 的主工作台整体结构。

当前阶段只规定主工作台的整体框架、页面组织方式、模块入口和 mock 数据放置规则。右侧具体模块页面的内容、字段、按钮和交互细节不在本文档中定义。

页面目标是形成一个本地小说世界引擎编辑器的主界面，而不是普通后台管理系统。

## 当前项目情况

当前工程已经具备 Electron + Vue3 + TypeScript 基础结构：

- Electron 内置菜单栏暂时不改。
- renderer 入口为 `src/App.vue`。
- 当前 `App.vue` 已有左侧导航和右侧工作区雏形，但内容仍是启动说明。
- 当前已有 `src/types/character.ts`，其中定义了人物 JSON 的基础结构。
- 人物、物品、地点、事件等真实 JSON 读写 API 尚未完整接入。

因此，后续 AI 应优先实现可运行的主工作台页面结构，不要一开始就实现完整数据持久化。

## 整体布局

页面内容位于 Electron 菜单栏下方，整体分为三块：

```text
主窗口内容
├─ 顶部项目栏
│  ├─ 小说名
│  ├─ 当前项目路径或项目状态
│  └─ 可选的保存状态、当前章节等轻量信息
├─ 左侧模块导航
│  ├─ 项目首页
│  ├─ 人物
│  ├─ 物品
│  ├─ 地点
│  ├─ 关系
│  ├─ 剧情
│  ├─ 时间线
│  └─ AI 上下文
└─ 右侧页面容器
   └─ 根据左侧导航或路由显示当前模块页面
```

顶部项目栏应突出小说名。小说名是当前工作项目的第一视觉锚点，可以先使用示例值，例如“未命名小说”或 mock 小说名。

左侧导航用于切换模块。它不是营销站点导航，也不是普通后台菜单，而是小说世界项目的资源入口。

右侧页面容器只负责承载当前模块页面。本文档不规定人物、物品、地点、关系、剧情、时间线或 AI 上下文页面内部如何展示信息。

## 页面组织方式

实现时应按真实项目开发方式组织页面结构，而不是写一个临时 demo 后再让后续 AI 重构。

如果使用多页面模块切换，应在本次实现中一次性完成必要的路由、视图目录和入口配置。不要先用临时本地状态模拟页面切换，再要求后续阶段引入路由重写。

推荐结构：

```text
src/
  App.vue
  router/
    index.ts
  views/
    ProjectHome.vue
    Characters.vue
    Items.vue
    Locations.vue
    Relations.vue
    Plots.vue
    Timeline.vue
    ContextExport.vue
```

如果项目尚未安装路由依赖，执行实现任务的 AI 应同步补齐依赖、配置和类型检查，确保完成后的代码可以直接运行。

## 视觉方向

整体视觉应接近桌面编辑器：

- 信息密度适中，偏工具型。
- 布局稳定，不要做大面积营销式 hero。
- 左侧导航清晰，按钮可以比普通菜单更像编辑器模块入口。
- 右侧页面容器保持足够空间，便于后续接入各模块页面。
- 可以使用边框、分隔线、浅色背景区分区域，但不要堆叠装饰性卡片。

线框图中的结构可以参考，但不要求照搬粗黑边框。真实 UI 应更像一个可长期使用的桌面工具。

## 模块入口要求

第一版主工作台至少提供这些模块入口：

- 项目首页
- 人物
- 物品
- 地点
- 关系
- 剧情
- 时间线
- AI 上下文

未完成模块可以显示空页面或最小占位页面，但占位内容只能说明当前模块名称，不要在本文档基础上自行扩展模块内部设计。

## Mock 数据规则

当前阶段尚未对接真实 JSON 项目数据时，可以使用 mock 数据。

mock 数据必须集中放在项目根目录的 `mock_data/` 目录下，不要直接散落在 Vue 组件中。

推荐结构：

```text
mock_data/
  novel.json
  characters.json
  items.json
  locations.json
  relations.json
  plots.json
  events.json
  timeline.json
```

renderer 页面可以从 `mock_data/` 导入或通过项目约定的 mock 读取方式使用这些数据。后续接入真实本地 JSON 文件时，应尽量保持页面组件的数据消费结构稳定。

## 数据边界

不要在 UI 组件里直接访问文件系统。后续接入真实数据时，应遵守以下调用方向：

```text
Vue component -> renderer api/store -> preload IPC -> Electron main -> JSON 文件
```

领域数据结构应继续遵守现有类型和 JSON 指南：

- 固定字段只保留系统真正需要的基础信息。
- 作者扩展设定进入 `customFields` 或等价开放字段。
- 读取和保存时必须保留未知字段。

## 建议实现顺序

1. 改造 `src/App.vue` 为主工作台布局。
2. 建立页面组织结构，必要时同步引入并配置 Vue Router。
3. 建立 `views/` 下的模块页面文件。
4. 建立项目根目录 `mock_data/`，放置页面需要的 mock 数据。
5. 左侧导航应能切换到对应模块页面，并正确显示选中状态。
6. 右侧页面容器只承载模块页面，不在主工作台中写死模块内部展示逻辑。

完成后应运行：

```bash
npm run typecheck
npm run build
```

验证通过后即可交付给用户继续细化各模块页面。
