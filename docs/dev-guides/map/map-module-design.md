# 地图模块设计

## 目标

地图模块用于帮助作者在可视化画布上标记、组织和浏览小说世界中的地点。

本模块不是真实地理信息系统，也不是复杂绘图软件。第一阶段只需要支持作者在一张简单地图上放置地点圆点、命名地点、编辑地点说明和自定义信息，并能通过子地图层级逐级进入更细的区域。

地图模块服务于“地点管理”和“世界状态维护”：

- 让作者快速知道地点之间的大致空间关系。
- 让地点说明、风土、人情、事件等结构化信息可以被右侧 Inspector 编辑。
- 让地点拥有稳定 ID，供地图标记和后续模块引用。
- 让 AI 上下文导出能读取地点实体数据，而不是依赖画布截图。

## 设计边界

- 默认使用本地 JSON 文件，不引入数据库。
- 不做在线地图瓦片、经纬度、真实 GIS 坐标。
- 不在第一阶段做复杂自由绘画、地形笔刷、路径寻路或自动布局。
- 不把地点信息直接写入 Konva 图形对象。
- 不把整张地图保存成不可读的单一大 JSON。
- 不要求子地图同时嵌套显示在父地图画布上，避免视觉混乱。

## 组件选择

第一阶段推荐使用 `Konva` 或 `vue-konva` 作为地图画布层。

当前地图页面已选择 `vue-konva + konva`，并接入 Electron IPC 与本地 JSON 文件读写。页面实现细节参考 `docs/dev-guides/map/map-page-prototype.md`。

Konva 负责：

- 渲染地图画布。
- 渲染地点圆点、地点名称和选中状态。
- 支持画布平移、缩放和地点拖拽。
- 处理地点点击、双击、拖拽结束等交互事件。
- 可选渲染背景图。

Konva 不负责：

- 定义地点业务数据。
- 定义子地图层级。
- 持久化 JSON 文件。
- 管理右侧 Inspector 表单状态。

如果后续需要更接近绘图软件的对象编辑、旋转、缩放控制点和对象序列化，可以再评估 `Fabric.js`。如果后续要做白板式自由绘制，可以评估 `tldraw`，但它和 Vue/Electron 的接入成本更高，不作为第一阶段默认方案。

底层 JSON 格式不能依赖 Konva。即使未来替换成 Fabric.js、SVG、Canvas 原生实现或其他图库，地点实体和地图视图数据仍应可用。

## 页面布局

地图模块应放在主工作台右侧页面容器中，不修改顶部项目栏和左侧模块导航。

推荐布局：

```text
地图页面
├─ 左侧面板
│  ├─ 地图层级树
│  ├─ 当前地图地点列表
│  └─ 新增地点、搜索、筛选等工具
├─ 中间画布
│  ├─ 当前地图标题和面包屑
│  ├─ 地点圆点和名称
│  ├─ 按住空白画布拖动平移
│  └─ 选中地点浮动工具条
└─ 右侧 Inspector
   ├─ 地点基础信息
   ├─ 地点描述
   ├─ 自定义字段
   └─ 子地图入口
```

### 左侧面板

左侧面板用于管理地图层级和当前地图内的地点。

地图层级树示例：

```text
世界地图
├─ 江南
│  ├─ 南京
│  │  └─ 秦淮河畔
│  └─ 扬州
└─ 北境
```

规则：

- 点击地图树节点切换当前地图。
- 当前地图高亮显示。
- 当前地图下方列出本地图内地点。
- 地点列表支持按名称和自定义字段搜索。
- 不在左侧展示完整地点详情，详情交给右侧 Inspector。

### 中间画布

中间画布只展示当前地图，不同时展开所有子地图。

交互规则：

- 点击空白画布：取消地点选中。
- 点击地点圆点：选中地点，并在右侧 Inspector 显示详情。
- 双击地点：如果该地点有关联子地图，进入子地图；如果没有子地图，保持选中状态。
- 按住空白画布拖动：平移当前地图视图，并保存到地图文件的 `viewport`。
- 拖拽地点：只改变该地点在当前地图视图中的坐标，不改变地点本身的业务含义。
- 点击新增地点后，在当前地图中心或用户点击位置创建地点。
- 画布平移只影响当前视图，不改变地点实体数据。

视觉规则：

- 普通地点使用圆点加名称。
- 有子地图的地点使用双圈、角标或小地图图标提示。
- 选中地点使用明确描边或高亮环。
- 选中地点附近可以出现浮动工具条，第一阶段只保留：编辑、删除、详情。
- 子地图入口优先使用地点上的小图标或右侧 Inspector 主按钮，不把大块子地图预览直接铺在父级画布上。

### 右侧 Inspector

右侧 Inspector 是地点信息的主要编辑入口。

固定字段建议只保留：

- 名称
- 类型
- 上级地点
- 描述

题材相关字段全部进入 `customFields`，例如：

- 风土
- 人情
- 宗教
- 禁忌
- 灵气浓度
- 驻军数量
- 治安
- 资源
- 交通

Inspector 规则：

- 未选中地点时，展示当前地图概要和操作入口。
- 选中地点时，展示该地点的固定字段和自定义字段。
- 新增或编辑自定义字段时，key 由作者输入，可以是中文。
- value 优先按 JSON 解析，解析失败时按普通字符串保存。
- 空 key 不保存。
- 重复 key 必须提示并阻止保存。
- 删除地点前必须确认，因为当前地图标记或子地图可能引用它。

## 子地图设计

子地图表示“某个地点内部还有更细一级地图”。

示例：

```text
世界地图
└─ 江南
   └─ 南京
      └─ 秦淮河畔
```

设计规则：

- 子地图是独立地图文件，不是父地图画布上的嵌入窗口。
- 一个地点第一阶段最多关联一张子地图。
- 进入子地图后，中间画布切换为子地图内容，顶部面包屑展示层级。
- 返回上级地图时，恢复父地图视图。
- 父地图中的地点圆点只代表“入口位置”，不代表子地图内部所有坐标。
- 删除带子地图的地点时，必须提示会影响子地图入口；第一阶段可以禁止直接删除，要求先解除或删除子地图。

## 数据格式

地图模块需要分离两类数据：

1. 地点实体：记录地点是什么。
2. 地图视图：记录地点在某张地图上如何显示。

### 项目目录结构

推荐结构：

```text
novel-project/
  locations/
    location_jiangnan.json
    location_nanjing.json
    location_qinhuai.json
  maps/
    map_world.json
    map_jiangnan.json
    map_nanjing.json
```

### 地点实体文件

地点实体保存到 `locations/*.json`。

示例：

```json
{
  "id": "location_nanjing",
  "name": "南京",
  "type": "城市",
  "parentLocationId": "location_jiangnan",
  "description": "江南重镇，商贸繁盛，士族云集。",
  "customFields": {
    "风土": "临江而兴，城内水道密布。",
    "人情": "士族讲究门第，商贾消息灵通。",
    "治安": "外城混乱，内城由巡防营严控。"
  },
  "schemaVersion": 1
}
```

字段说明：

- `id`：稳定地点 ID，用于事件、人物、物品、地图视图引用。
- `name`：显示名称，可以修改。
- `type`：地点类型，例如国家、地区、城市、建筑、秘境。
- `parentLocationId`：上级地点 ID，没有上级时为 `null` 或省略。
- `description`：地点介绍。
- `customFields`：作者自定义字段。
- `schemaVersion`：结构版本。

第一阶段不要在地点实体中加入 `controllerId`、`eventIds`、`defaultMapId`。

- 控制者属于势力或世界状态能力，当前地图 MVP 不需要。
- 事件引用应由事件模块记录，例如事件文件自己引用 `locationId`，不要让地点文件维护事件列表。
- 子地图关系由 `maps/*.json` 的 `rootLocationId`、`parentMapId` 和 `parentLocationId` 表达，不需要在地点文件中额外保存默认地图 ID。

### 地图视图文件

地图视图保存到 `maps/*.json`。

示例：

```json
{
  "id": "map_jiangnan",
  "name": "江南地图",
  "rootLocationId": "location_jiangnan",
  "parentMapId": "map_world",
  "parentLocationId": "location_jiangnan",
  "background": null,
  "viewport": {
    "x": 0,
    "y": 0,
    "scale": 1
  },
  "pins": [
    {
      "id": "pin_nanjing",
      "locationId": "location_nanjing",
      "x": 420,
      "y": 280,
      "color": "#2563eb",
      "icon": "city",
      "showLabel": true
    },
    {
      "id": "pin_yangzhou",
      "locationId": "location_yangzhou",
      "x": 620,
      "y": 360,
      "color": "#16a34a",
      "icon": "city",
      "showLabel": true
    }
  ],
  "schemaVersion": 1
}
```

字段说明：

- `id`：稳定地图 ID。
- `name`：地图显示名称。
- `rootLocationId`：这张地图描述的地点范围。
- `parentMapId`：上级地图 ID，没有上级时为 `null` 或省略。
- `parentLocationId`：父地图中进入本地图的地点 ID。
- `background`：背景图信息，第一阶段可以为 `null`。
- `viewport`：用户上次查看该地图时的平移和缩放状态。
- `pins`：当前地图上的地点标记。
- `schemaVersion`：结构版本。

`pins` 只保存显示信息，不保存地点介绍。地点介绍必须通过 `locationId` 去读取 `locations/*.json`。

### 背景图格式

第一阶段背景图可以先不实现。如果实现，应使用相对项目目录的资源路径。

示例：

```json
{
  "type": "image",
  "path": "assets/maps/jiangnan.png",
  "opacity": 1
}
```

不要保存绝对路径，避免小说项目换电脑后失效。

## 开发方案

### 建议文件组织

第一阶段实现时可以按以下结构组织：

```text
src/
  types/
    location.ts
    map.ts
  views/
    Locations.vue
    map/
      useMapWorkbench.ts
      MapSidebar.vue
      MapCanvas.vue
      MapInspector.vue
```

如果项目已有更合适的模块组织，以现有模式为准。

### 类型层

需要定义：

- `LocationFile`
- `MapFile`
- `MapPin`
- `MapViewport`
- `MapBackground`

类型层应提供运行时校验函数，例如：

- `isLocationFile`
- `isMapFile`

校验规则：

- 必须有 `id`、`name`、`schemaVersion`。
- `customFields` 必须是对象，缺失时可补 `{}`。
- `pins` 必须是数组。
- `pin.locationId` 必须引用已存在地点；加载时可以先记录缺失引用并在 UI 中提示。
- 读取后再保存必须保留未知字段。

### 数据流

Vue 页面不得直接访问文件系统。

调用方向：

```text
Vue component -> renderer api/store -> preload IPC -> Electron main -> JSON 文件
```

地图模块需要的最小 API：

- 读取全部地点。
- 读取全部地图。
- 保存单个地点。
- 保存单个地图。
- 创建地点。
- 创建地图。
- 删除地点。
- 删除地图。

保存时应只保存被修改的 JSON 文件，不要重写整个项目目录。

### 画布状态

需要区分两种状态：

- 临时 UI 状态：当前选中 pin、拖拽中坐标、悬浮工具条位置、编辑弹框开关。
- 持久化状态：地图 `viewport`、`pins` 坐标、地点实体字段。

拖拽地点时：

1. 拖拽过程中只更新临时 UI 状态。
2. 拖拽结束后更新当前 `MapFile.pins` 中对应 pin 的坐标。
3. 保存当前地图文件。
4. 不修改 `LocationFile`，除非用户同时编辑地点信息。

### 新增地点流程

第一阶段推荐流程：

1. 用户点击“新增地点”。
2. 用户在画布上点击位置，或系统使用当前画布中心。
3. 弹出轻量表单，输入地点名称和类型。
4. 创建 `LocationFile`。
5. 在当前 `MapFile.pins` 中新增一个 pin，引用新地点 ID。
6. 保存地点文件和地图文件。
7. 自动选中新地点，并在右侧 Inspector 展示。

### 编辑地点流程

1. 用户点击地点圆点。
2. 右侧 Inspector 显示地点信息。
3. 用户编辑名称、描述、自定义字段等。
4. 保存前校验自定义字段 key。
5. 保存 `locations/*.json` 中对应地点文件。
6. 画布上的名称根据地点实体名称刷新。

### 子地图创建流程

1. 用户选中地点。
2. 在右侧 Inspector 点击“创建子地图”。
3. 系统创建新的 `MapFile`，其 `rootLocationId` 指向当前地点。
4. 新地图的 `parentMapId` 指向当前地图，`parentLocationId` 指向当前地点。
5. 保存新地图文件。
6. 可选择立即进入子地图。

## MVP 范围

第一阶段只实现：

- 地图列表和层级树。
- 当前地图画布。
- 地点圆点、地点名称、选中态。
- 新增地点。
- 按住空白画布拖动平移地图。
- 拖拽地点。
- 编辑地点名称、类型、描述和自定义字段。
- 创建并进入子地图。
- 面包屑返回上级地图。
- JSON 读写和运行时校验。

第一阶段不实现：

- 真实 GIS 地图。
- 多人协作。
- 路线、区域、多边形地块。
- 复杂自由绘制。
- 地形笔刷。
- AI 自动生成地图。
- 地图导出图片。
- 多背景图图层。
- pin 与事件的复杂时间过滤。
- 未实现前不展示适配视图、缩小、放大按钮。

## 视觉与交互规则

- 地图页面应保持工具型桌面编辑器风格，不做营销式大卡片。
- 中间画布优先占据主要空间。
- 右侧 Inspector 是主要编辑区域，不在画布上堆叠大型表单。
- 浮动工具条只放高频动作，避免遮挡地图。
- 子地图通过面包屑和树形层级表达，不在父地图上嵌套大窗口。
- 删除、解除子地图、覆盖背景图等破坏性操作必须确认。
- 所有保存动作都应尽量局部保存对应 JSON 文件。

## 与其他模块的关系

- 地点模块：地图中的每个 pin 引用一个地点实体。
- 事件模块：后续由事件文件主动引用地点 ID，不在地点文件中维护事件列表。
- 人物模块：人物可以通过自定义字段或后续引用表达所在地点。
- 物品模块：物品可以通过自定义字段或后续引用表达所在地点。
- 势力模块：控制权属于后续扩展，不进入第一阶段地点实体。
- AI 上下文导出：应读取地点实体、地图层级和必要的地点引用，不依赖画布截图。

## 后续扩展方向

审核通过并完成 MVP 后，可以逐步扩展：

- 路线：道路、河流、航线、传送阵。
- 区域：国家边界、城区、禁地范围。
- 图层：政治、交通、资源、事件热区。
- 时间过滤：按章节显示某个时期的地点控制权或事件。
- 背景图导入：导入作者手绘图作为底图。
- 地图快照：导出 PNG 供作者写作参考。
- AI 建议变更：AI 根据章节分析提出新增地点、移动地点、更新描述等 JSON patch，保存前必须展示差异并由用户确认。
