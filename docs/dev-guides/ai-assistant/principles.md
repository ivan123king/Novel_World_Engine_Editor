# AI小助手核心原则

## A/B 分离

小说工具 A 只负责小说编辑、数据管理、AI UI、AI 服务配置和 API 调用。

Novel AI 服务 B 只负责 AI 能力，包括项目读取、索引、搜索、RAG、Prompt 组织和 LLM 调用。

A 不实现 Elasticsearch、向量检索、Embedding、RAG、Prompt 组装、LLM API 和 AI 知识库。

## A 的数据为准

A 项目目录中的 JSON 和正文是 Source of Truth。

B 的 Elasticsearch 数据、向量数据、AI 缓存和索引状态不是小说真实数据，不能作为唯一数据来源。

## 当前项目优先

AI 回答小说相关问题时，知识优先级为：

```text
当前项目结构化数据
    ↓
当前项目正文 / 剧情
    ↓
用户挂载的参考知识
    ↓
小说写作知识
    ↓
LLM 自身知识
```

当前项目设定与参考知识冲突时，以当前项目设定为准。

## AI 不直接写入

第一阶段 B 只读取小说项目，不直接修改小说项目 JSON。

AI 输出默认只能是回答、分析、建议和写作参考。

未来需要修改小说数据时，必须走以下流程：

```text
AI 建议
    ↓
A 展示修改内容 / Diff
    ↓
用户确认
    ↓
A 执行 JSON 修改
    ↓
B 重新同步索引
```

## 本地优先和隐私

小说正文和项目数据默认保存在用户本地。

B 在本地执行项目读取、索引、检索和 RAG。只有调用远程 LLM 时，才发送当前请求必要的上下文。

禁止默认把整个小说项目发送给远程 LLM。

## 知识库边界

B 可以维护独立 AI 知识库，内容包括写作知识、人物塑造、剧情节奏、世界观设计和用户授权资料。

知识库只是参考资料，不能覆盖当前小说项目的真实设定。

导入参考小说或外部资料时，必须遵守版权和授权要求。
