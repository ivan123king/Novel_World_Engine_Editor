# AI小助手系统设计

## 设计目的

为 Novel World Engine Editor 提供独立、可扩展、可替换的 AI 能力。

系统由两个工程组成：

- 小说工具 A：当前仓库，负责小说编辑、小说数据管理和 AI小助手界面。
- Novel AI 服务 B：后续独立工程，负责 AI 检索、索引、知识库、RAG 和 LLM 调用。

## 总体结构

```text
小说工具 A
  Electron + Vue3 + TypeScript
  小说编辑 / JSON 数据 / AI小助手 UI
        |
        | HTTP API
        v
Novel AI 服务 B
  项目注册 / 数据读取 / 搜索 / RAG / LLM
        |
        v
远程 LLM 或本地模型
```

## 工程边界

A 是小说编辑器，不实现复杂 AI 能力。

B 是本地 AI 服务，不提供小说编辑界面，也不直接改写 A 的小说 JSON。

第一阶段 A 与 B 通过 HTTP REST API 通信。AI 对话后续可使用 SSE 返回流式结果。

## 数据关系

小说项目目录中的 JSON 和正文永远是小说真实数据源。

B 建立的全文索引、向量索引、AI 缓存和知识库挂载状态都只是 AI 使用的数据副本或索引，可以删除并重新生成。

```text
A 小说项目数据
        |
        | 读取 / 同步
        v
B AI 索引和缓存
        |
        | 检索 / RAG
        v
AI 回复
```

## 最终形态

用户在 A 中编辑小说、打开 AI小助手并输入自然语言问题。A 把当前项目身份和用户消息发送给 B。B 读取或检索当前小说项目数据，组装上下文，调用模型并返回回答和引用来源。

未来如果 AI 需要修改小说设定，B 只返回建议变更；A 负责展示 Diff，并在用户确认后写入项目 JSON。
