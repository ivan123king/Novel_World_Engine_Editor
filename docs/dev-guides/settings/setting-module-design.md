# 设定模块设计

## 目的

设定模块用于记录小说世界中跨人物、物品、地点和剧情长期成立的背景信息，例如世界背景、修炼规则、境界体系、组织制度、历史常识、魔法规则、科技规则等。

设定不是普通备注，也不是章节正文。它保存的是作者在写作时需要反复遵守的“世界规则”和“背景事实”，后续应能被 AI 上下文导出读取，用来减少设定冲突。

当前阶段保持轻量：每条设定只有标题和内容。内容已支持基础富文本编辑，但只开放文字排版能力，不支持图片、附件等会扩大数据边界的内容类型。

## 设计原则

- 设定模块是小说项目资源的一类，放在主工作台模块导航中，并展示在人物模块之前。
- 保持本地优先：设定数据保存为用户项目目录中的 JSON 文件，不引入数据库。
- 保持轻量：当前阶段只支持标题和基础富文本内容，不做分类、标签、版本历史或复杂引用关系。
- 保持可携带：每条设定使用独立 JSON 文件，方便作者阅读、版本管理、恢复和对比。
- 保持可扩展：读取和保存时保留未知字段，为后续富文本、分类、引用实体、AI 变更建议等能力预留空间。
- 保持可审查：后续 AI 只能提出设定变更建议，写入 JSON 前必须展示差异或确认步骤。
- 不改变用户习惯：交互风格参考人物模块，列表选择后在 Inspector 区域展示详情，新建和编辑使用弹框。

## 页面入口

- 主工作台左侧模块导航新增“设定”Tab。
- “设定”Tab 的顺序放在“人物”之前。
- 点击“设定”Tab 后，右侧页面容器进入设定模块。
- 设定模块内部采用列表 + 内容详情结构：
  - 左侧展示设定列表。
  - 右侧 Inspector 展示当前选中设定的标题和内容。

如果当前工作台已有统一的模块布局组件，应优先复用现有布局、按钮、弹框和空状态组件，不在设定模块内重复实现公共 UI。

## 功能范围

第一阶段必须包含：

- 查看设定列表。
- 点击设定列表项后展示设定内容。
- 新建设定，使用弹框输入标题和内容。
- 编辑设定，使用弹框修改标题和内容。
- 删除设定。
- 空列表时展示空状态和新建入口。
- 标题搜索，至少支持按标题过滤；内容搜索可后续补充。

第一阶段不做：

- 图片、附件、表格等复杂富文本能力。
- Markdown 预览。
- 设定分类树。
- 标签系统。
- 设定之间的引用关系图。
- 与人物、物品、地点的双向引用维护。
- AI 自动写入设定 JSON。

## 表单规则

新建和编辑弹框字段：

- 标题：单行输入，必填，去除首尾空白后不能为空。
- 内容：基础富文本编辑器，允许为空，但建议 UI 保留足够高度，便于输入较长规则说明。

保存规则：

- 新建设定时生成稳定 ID。
- 编辑设定时保留原对象的 `id`、`schemaVersion` 和未知字段。
- 标题为空时阻止保存并在弹框内提示。
- 内容按 HTML 字符串保存，不解析 JSON，不支持图片、附件等外部资源。
- 取消弹框不修改当前数据。

## 详情展示

Inspector 至少展示：

- 设定标题。
- 设定内容。
- 编辑入口。
- 删除入口。

内容为空时，详情区可以展示简短空状态，但不要自动填充占位内容到 JSON。

## 数据格式要求

设定数据保存为独立 JSON 文件：

```text
data/
  settings/
    setting_xxx.json
```

每个设定文件对应一个设定实体：

```ts
{
  id: string;
  title: string;
  content: string;
  contentFormat?: "plain-text" | "html";
  schemaVersion: 1;
}
```

字段说明：

- `id`：系统稳定 ID，用于未来引用、AI 建议变更和文件名生成。
- `title`：设定标题，作者可见。
- `content`：设定正文，当前阶段保存为 Tiptap 生成的基础 HTML 字符串；旧文件仍可保存纯文本。
- `contentFormat`：内容格式，新增或编辑后保存为 `html`；旧文件缺失时按 `plain-text` 兼容读取。
- `schemaVersion`：结构版本，第一阶段固定为 `1`。

示例：

```json
{
  "id": "setting_realm_system",
  "title": "修炼境界体系",
  "content": "<p>炼气、筑基、金丹、元婴、化神。</p><p>每一境界分初期、中期、后期、圆满。</p>",
  "contentFormat": "html",
  "schemaVersion": 1
}
```

## 文件与 ID 规则

- 设定 ID 同时作为文件名主体，只允许字母、数字、下划线和短横线。
- 文件名格式建议为 `{id}.json`，例如 `setting_realm_system.json`。
- 新建时如果标题为中文，ID 仍应生成安全字符串，例如 `setting_` 加短随机 ID 或时间序列。
- 单个坏文件不应阻断整个设定列表加载，应在页面错误区展示非致命错误。
- 读取后再保存时必须保留当前版本不认识的顶层字段。

## 列表顺序

第一阶段不强制实现拖动排序。

在没有拖动排序能力时，设定列表默认按设定 JSON 文件创建时间倒序展示。新建设定应出现在列表最前面，并且刷新或重新打开项目后仍保持新建优先。

如果后续为设定列表增加拖动排序，应将排序信息保存到独立文件，不要写入设定实体文件：

```text
data/
  list-orders/
    settings.json
```

排序文件格式沿用现有列表排序规则：

```json
{
  "entityType": "settings",
  "ids": ["setting_realm_system", "setting_world_background"],
  "schemaVersion": 1
}
```

## 富文本边界

当前富文本只允许基础文字结构：

- 段落
- 二级、三级标题
- 加粗、斜体、删除线
- 无序列表、有序列表
- 引用
- 撤销、重做

不要在设定内容中引入图片、附件、视频、iframe、外链卡片或编辑器私有二进制状态。`content` 继续保持可阅读的字符串，便于 JSON 文件离开应用后被检查、版本管理和恢复。

任何 schema 变更都必须包含迁移说明，并保证旧项目中的纯文本设定可以继续读取。

## 开发指示

- 设定模块 Vue 文件顶部添加中文文件功能注释。
- 设定相关函数添加中文函数注释，说明其负责列表加载、表单提交或 JSON 转换等职责。
- Vue 页面不得直接访问 Node 文件系统，必须通过 renderer API、preload IPC 和 Electron main process 服务读写 JSON。
- TypeScript 类型建议放在 `src/types/setting.ts`。
- renderer API 建议放在 `src/api/settingApi.ts`。
- Electron main process 服务建议放在 `electron/main/settings/`。
- mock 数据如需使用，放在 `mock_data/` 中，并保持与最终 JSON 结构一致。

## 验证

实现设定模块后运行：

npm run typecheck
npm run build
