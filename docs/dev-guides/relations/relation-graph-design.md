# 关系图谱设计

## 目标

关系图谱模块用于让作者维护小说世界中“当前成立的关系”和“关系为什么变化到当前状态”。

本模块不是普通关系表，也不是单纯展示网络图。它要同时支持：

- 人物图谱：系统默认图谱，节点自动来自当前项目已定义人物。
- 用户自定义图谱：由作者自己创建图谱和块，例如“青城山”“华山派”“朝堂派系”“神器归属”。
- 每张图谱使用同一套编辑界面：左侧块列表，中间关系图，右侧关系时间轴。
- 关系当前状态和历史变化分离。中间图谱展示当前关系，右侧时间轴解释关系变化过程。

## 设计原则

- 底层 JSON 不依赖 AntV G6。G6 只负责渲染和交互，不能污染持久化数据结构。
- 人物图谱是默认图谱，但不是唯一图谱。用户可以创建任意数量的自定义图谱。
- 所有图谱的页面结构保持一致，避免人物图谱和自定义图谱形成两套 UI。
- 图谱左侧块列表支持拖拽排序，排序属于工作台展示偏好，不写入块本身的题材设定。
- 关系历史使用用户可输入的时间标记，不强制要求章节号。章节号或排序值只作为可选辅助字段。
- 同一张图谱中，同一对块只能存在一条当前关系，方向相反也视为同一对关系。关系从“敌对”变成“合作”时，应编辑已有关系并补充历史记录，而不是新增第二条平行关系。
- 删除图谱、删除块、删除关系都属于高风险操作，必须经过确认。
- AI 后续只能提出关系变更建议，保存前必须展示差异并由用户确认。

## 页面结构

关系模块进入后显示一个图谱编辑器。

```text
关系页面
├─ 顶部图谱选择栏
│  ├─ 人物图谱固定入口
│  └─ 自定义图谱下拉
│     ├─ 新建图谱
│     ├─ 切换自定义图谱
│     └─ 删除自定义图谱
├─ 左侧块列表
│  ├─ 搜索块
│  ├─ 块列表，支持拖拽排序
│  └─ 新建块，仅自定义图谱可用
├─ 中间关系树画布
│  ├─ 当前选中块作为根节点
│  ├─ 与根节点直接相连的块作为第一层子节点
│  ├─ 首版只展示根节点的一跳直接关系，不继续展开子节点关系
│  ├─ 添加关系
│  └─ 选中节点或关系
└─ 右侧关系时间轴
   ├─ 当前选中关系
   ├─ 当前关系状态
   ├─ 关系变化记录
   └─ 新增、编辑、删除变化记录
```

顶部图谱选择栏是管理“多张图谱”的主入口。不要只做一个静态 Tab，因为用户需要新建和删除图谱。

顶部不展示数据保存路径。保存路径属于实现细节，不应占据关系编辑器的主要视觉焦点。

图谱管理入口应保持克制，不要把下拉框和多个按钮全部平铺成一排造成噪音。首版可以保留人物图谱入口、自定义图谱切换和必要操作按钮，但需要用紧凑工具组呈现；后续可以进一步收束到“更多”菜单。

推荐控件：

- 人物图谱固定显示在顶部，作为系统默认图谱入口，不放进自定义图谱下拉列表。
- 自定义图谱下拉：只展示用户创建的图谱，例如“青城山关系”“朝堂派系”“神器归属”。
- 自定义图谱下拉顶部固定显示“新建图谱”，避免图谱过多时用户必须滚动到底部才能新建。
- 自定义图谱下拉中的每个图谱行右侧显示小 `X` 删除图标。
- 删除图标只负责触发删除确认；点击图谱行本身负责切换图谱。
- 需要重命名时，可以在图谱行右键菜单或更多菜单中提供。
- 人物图谱是系统默认图谱，不显示删除入口。

图谱下拉建议结构：

```text
顶部图谱栏
├─ 人物图谱                 系统默认，固定显示
└─ 自定义图谱 v

自定义图谱下拉菜单
├─ + 新建图谱
├─ 青城山关系               X
├─ 朝堂派系                 X
└─ 神器归属                 X
```

## 图谱类型

### 人物图谱

人物图谱由系统默认创建，不允许用户删除。

人物图谱的块来自当前项目的 `characters/*.json`：

- 新增人物后，人物图谱自动出现该人物块。
- 删除人物后，人物图谱应移除或标记对应人物块为已删除。
- 人物块名称来自人物文件的 `name`，引用使用人物稳定 `id`。
- 人物图谱中的人物块可以保存位置和显示偏好，但人物名称、基础设定必须以人物文件为准。
- 人物图谱中不允许直接新建普通块。要新增人物，应跳转到人物模块创建。

人物图谱仍然允许作者创建、编辑和删除人物之间的关系。

### 自定义图谱

自定义图谱由用户创建。每张图谱可以自由创建块和关系。

自定义块可以是纯图谱块，也可以引用项目中的现有实体：

- 人物
- 物品
- 地点
- 势力
- 事件
- 其他后续实体

第一版可以只支持纯图谱块，预留 `entityRef` 字段给后续引用实体。

## 左侧块列表

左侧块列表展示当前图谱中的块。

行为要求：

- 支持搜索。
- 支持拖拽排序。
- 点击块后，中间画布高亮对应节点和直接关系。
- 自定义图谱中，右键块显示块操作菜单。
- 人物图谱中，块的新增和删除入口不可用；编辑人物基础信息应跳转到人物模块。
- 自定义图谱中，允许新建、重命名、删除块。

块右键菜单建议：

```text
重命名块
删除块
```

人物图谱中的人物块第一版不提供右键菜单，避免人物管理和关系图谱编辑混在一起。

块列表排序建议复用 `list-orders` 思路，但按图谱保存：

```text
list-orders/
  relation-graph-blocks/
    graph_default_characters.json
    graph_qingcheng_conflict.json
```

排序文件只保存块 ID 顺序，不改变块自身数据。

## 中间关系树画布

中间画布展示当前图谱中“当前选中块”为根的树形关系视图，而不是一次性展示整张图谱的全部节点和全部关系。

这是关系模块的核心交互约束：当图谱包含上百个人物、地点或势力时，画布必须以当前选中块为根组织一棵可滚动的关系树。比如在左侧块列表点击“张三”时，张三作为根节点，张三的直接关系作为第一层分支；在左侧块列表点击“李四”时，画布切换为李四作为根节点的关系树，张三的无关关系不出现在画布上。

该规则适用于所有图谱类型：

- 人物图谱：点击左侧某个人物块，只展示该人物为根的关系树。
- 自定义图谱：点击左侧某个自定义块，只展示该块为根的关系树。
- 若选中一条关系线，画布仍以当前根节点为中心，右侧时间轴展示该关系。
- 首版树深度固定为 1 层，只展示根节点的一跳直接关系，避免子节点自己的关系混入当前根节点视图。后续如需更深层级，必须提供明确的层级深度开关。

底层 JSON 仍保存完整图谱。树形展示只属于 renderer 视图过滤逻辑，不改变 `nodes`、`edges` 的持久化结构。

画布行为要求：

- 点击左侧块列表中的块：切换画布根节点，左侧同步高亮该根节点。
- 点击画布中的根节点：保持当前根节点，不改变右侧关系选择。
- 点击画布中的子节点：不切换左侧块列表选中项，不把该子节点改成根节点；行为等同于点击根节点到该子节点之间的关系线，右侧显示这条关系的当前状态和时间轴。
- 点击关系线：选中关系，右侧显示时间轴，画布保持当前根节点的树形视图。
- 悬浮关系线：高亮关系两端的块。
- 切换左侧块列表中的块后：画布立即切换为该块为根的树形关系，之前根节点的无关关系不再显示。
- 画布优先使用树形自动布局，而不是力导向或散点布局。
- 画布区域可纵向滚动，以便作者查看整棵树；不要依赖缩放状态条来提示布局信息。

画布上的关系线只展示树中可见节点之间的“当前关系”，例如：

```text
张三 -- 敌对 --> 李四
青城山 -- 争夺灵脉 --> 华山派
神器 -- 持有者 --> 林辰
```

关系线标签建议展示：

- 当前关系名称
- 强度，可选

不要在关系线上展示完整历史。历史只在右侧时间轴中展示。

画布底部不要展示“缩放 / 布局 / 聚焦”等状态胶囊。它们不是核心编辑对象，会增加视觉噪音。

## 右侧关系时间轴

右侧时间轴只在选中关系线后显示完整内容。未选中关系时显示空状态。

右侧应分为两块。关系变化记录区域的新增入口必须位于时间轴列表上方，新增记录后应优先出现在时间轴顶部，便于作者先处理最近变化或刚录入的变化。

右侧“当前关系”不需要再重复显示一个强度胶囊。关系名称就是 `current.type`；强度作为普通字段展示即可。右侧应减少按钮和下拉框等显性控件，只展示当前关系、关系两端、当前原因和必要操作。

如果关系没有任何历史记录，不要自动创建一条空记录。应显示空状态并保留“新增记录”入口，让作者决定是否记录历史变化。

```text
当前关系
关系变化记录
├─ 新增记录
└─ 时间轴记录列表
```

当前关系字段：

- 关系名称
- 关系强度，可选
- 当前原因

关系变化记录字段：

- 时间标记：用户输入，例如“第20章”“黑风寨事件后”“大婚前夜”“当前”。
- 排序值：可选数字，用于排序，不展示为强制章节。
- 当时关系名称。
- 当时关系强度，可选。
- 变化原因。

时间轴展示顺序默认使用“当前/最新在上，旧变化向下”。排序优先使用 `order`，其次使用 `chapter`，最后使用创建时间；数值越大的记录越靠上。不要强迫作者必须填写章节号。

## 右键菜单

第一版只使用少量右键菜单，避免把关系图谱做成复杂专业画图工具。

顶部自定义图谱下拉中应保留可见的新建入口。右键菜单作为快捷入口，不作为唯一入口。

图谱右键菜单：

```text
重命名图谱
删除图谱
```

自定义块右键菜单：

```text
重命名块
删除块
```

删除规则：

- 删除图谱：人物图谱不允许删除；自定义图谱删除前弹窗确认。
- 删除块：如果块有关联关系，确认弹窗必须说明会同时删除或断开哪些关系。
- 删除关系：确认弹窗展示关系两端和当前关系名称。

## 数据文件结构

推荐项目目录：

```text
novel-project/
  relation-graphs/
    graph_default_characters.json
    graph_qingcheng_conflict.json
  list-orders/
    relation-graphs.json
    relation-graph-blocks/
      graph_default_characters.json
      graph_qingcheng_conflict.json
```

`list-orders/relation-graphs.json` 保存自定义图谱下拉顺序。人物图谱固定在顶部，不依赖该排序文件。

`list-orders/relation-graph-blocks/*.json` 保存每张图谱左侧块列表顺序。

## 图谱 JSON

每张图谱一个 JSON 文件。

```json
{
  "id": "graph_default_characters",
  "name": "人物图谱",
  "kind": "character-default",
  "description": "系统默认人物关系图谱",
  "nodes": [
    {
      "id": "node_char_zhangsan",
      "label": "张三",
      "kind": "entity-ref",
      "entityRef": {
        "type": "character",
        "id": "char_zhangsan"
      },
      "view": {
        "x": 120,
        "y": 240
      },
      "customFields": {}
    }
  ],
  "edges": [
    {
      "id": "edge_zhangsan_lisi",
      "from": "node_char_zhangsan",
      "to": "node_char_lisi",
      "current": {
        "type": "敌对",
        "score": 80,
        "reason": "身份泄露后，双方公开决裂"
      },
      "history": [
        {
          "id": "hist_001",
          "label": "黑风寨事件后",
          "order": 40,
          "type": "临时合作",
          "score": 50,
          "reason": "共同对抗黑风寨"
        }
      ],
      "customFields": {}
    }
  ],
  "view": {
    "layout": "force",
    "zoom": 1,
    "pan": {
      "x": 0,
      "y": 0
    }
  },
  "createdAt": "2026-08-11T00:00:00.000Z",
  "updatedAt": "2026-08-11T00:00:00.000Z",
  "schemaVersion": 1
}
```

字段说明：

- `kind`：`character-default` 表示系统默认人物图谱；`custom` 表示用户自定义图谱。
- `nodes`：当前图谱的块。人物图谱节点引用人物实体，人物名称以人物文件为准，节点内只保存图谱位置和显示偏好。
- `edges`：当前图谱的关系。
- `current`：关系当前状态，用于中间画布展示。
- `history`：关系变化记录，用于右侧时间轴展示。
- `view`：画布布局信息，只服务 UI，不参与小说世界事实判断。
- `customFields`：作者自定义扩展字段，读取保存时必须保留。

## 图谱列表排序 JSON

```json
{
  "entityType": "relation-graphs",
  "ids": ["graph_qingcheng_conflict", "graph_court_factions"],
  "schemaVersion": 1
}
```

该文件只保存自定义图谱顺序。人物图谱固定显示在顶部，即使排序文件缺失也必须可用。

## 块列表排序 JSON

```json
{
  "entityType": "relation-graph-blocks",
  "graphId": "graph_qingcheng_conflict",
  "ids": ["node_qingcheng_mountain", "node_huashan_faction"],
  "schemaVersion": 1
}
```

拖拽块列表后立即保存。保存失败时回滚界面顺序并提示错误。

## 新建流程

### 新建图谱

1. 用户点击自定义图谱下拉顶部的“新建图谱”。
2. 弹窗输入图谱名称和说明。
3. 创建 `relation-graphs/{graphId}.json`。
4. 将图谱 ID 追加到 `list-orders/relation-graphs.json`。
5. 自动切换到新图谱。

### 新建块

1. 仅自定义图谱允许新建块。
2. 用户点击左侧“新建块”。
3. 输入块名称。
4. 追加到当前图谱 `nodes`。
5. 追加到当前图谱块排序文件。

### 新建关系

1. 用户点击“添加关系”。
2. 选择起点块和终点块。
3. 保存前检查当前图谱中是否已存在这两个块之间的关系；若已存在，提示用户编辑已有关系，不允许重复新增。
4. 输入当前关系名称、强度、当前原因。
5. 可选输入第一条变化记录。
6. 保存到当前图谱 `edges`。

## 删除流程

### 删除图谱

- 人物图谱不可删除。
- 自定义图谱删除前展示图谱名称、块数量、关系数量。
- 删除图谱文件后，从图谱排序文件移除 ID。
- 同时删除对应块排序文件。

### 删除块

- 人物图谱中的人物块不可在关系模块删除；如需删除人物，应到人物模块处理。
- 自定义图谱删除块时，如果存在关联关系，确认弹窗必须列出受影响关系数量。
- 删除块后同步删除或断开关联关系。第一版建议直接同步删除关联关系，并在确认弹窗中说明。

### 删除关系

- 删除前展示起点、终点、当前关系名称。
- 删除后右侧时间轴清空，画布取消选中。

## AntV G6 使用边界

G6 可用于：

- 渲染节点和关系线。
- 画布缩放和拖动。
- 点击和悬浮交互。
- 自动布局。
- 高亮选中节点和关系。

G6 不负责：

- 决定 JSON 文件结构。
- 保存关系历史。
- 保存小说世界事实。
- 直接访问本地文件。

实现时应先把图谱 JSON 转换成 G6 数据，再传给 G6。保存时只保存领域 JSON，不保存 G6 内部对象。

## 首版实现范围

第一版建议只实现：

- 默认人物图谱。
- 用户自定义图谱的新建、重命名、删除。
- 顶部人物图谱固定入口和自定义图谱下拉。
- 左侧块列表搜索和拖拽排序。
- 自定义图谱块的新建、重命名、删除。
- 中间画布按当前选中块展示树形关系视图。
- 关系的新建、编辑、删除。
- 右侧关系时间轴的新建、编辑、删除。

暂缓：

- AI 自动分析关系。
- 复杂图谱分组。
- 多图谱批量操作。
- 跨图谱引用校验。
- 高级布局模板。
