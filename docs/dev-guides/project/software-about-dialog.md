# 软件关于弹框设计

## 目标

本文档用于指导应用顶部系统菜单中的“关于”功能。

“关于”模块属于应用自身信息展示，不属于任何一部小说项目的数据，也不读写 `novel.json`、人物、物品、地图、关系图谱、剧情或时间线等小说世界状态文件。

第一版只实现一个从系统菜单打开的关于弹框，展示软件名称、简介、作者和联系方式。所有展示内容写死在 renderer 页面代码中，不引入 JSON 配置，不提供编辑能力。

## 软件命名

应用中文名称统一为：

```text
佳依创式
```

界面展示规则：

- 顶部菜单、关于弹框标题和关于弹框主标题都使用 `佳依创式`。
- 关于弹框中软件名称居中显示。
- 不再在关于弹框中突出展示旧名称 `Novel World Engine Editor`。如后续需要保留英文内部代号，只能作为开发文档或包名使用，不作为用户第一视觉的软件名称。

## 菜单结构

Electron 顶部菜单栏在 `系统` 一级菜单下增加入口：

```text
系统
├─ 系统配置
└─ 关于佳依创式
```

菜单行为：

- 用户点击 `系统 > 关于佳依创式` 后，由 main process 向 renderer 发送打开关于弹框的事件。
- renderer 接收事件后展示全局关于弹框。
- 关于弹框不依赖当前是否已打开小说项目。未打开项目时也必须可用。

该入口不放入“小说”菜单，因为它展示的是应用信息，不是当前小说项目的操作。

## 展示内容

关于弹框第一版展示以下写死内容：

```text
佳依创式

一款本地优先的长篇小说世界引擎编辑器，用于维护故事世界的当前状态、人物关系、剧情事件与可供 AI 写作使用的上下文。

作者：GPT5.5、刘伟
联系方式：lw18751836671@163.com
```

实现时可以按视觉层级拆分为软件名、简介、作者信息和联系方式四块，但文本内容不从外部配置读取。

## 背景资源

关于弹框需要使用背景图：

```text
src/assets/about.jpg
```

当前资源如果在仓库中以 `about.JPG` 等大小写不一致的文件名存在，实施时应统一整理为 `about.jpg`，并在 Vue 组件中通过 `@/assets/about.jpg` 引入。这样可以避免未来在大小写敏感的构建或打包环境中出现资源找不到的问题。

背景图使用规则：

- 背景图只用于关于弹框视觉，不写入用户小说项目目录。
- 背景应覆盖弹框主体区域，可以使用 `background-size: cover` 和 `background-position: center`。
- 为保证文字可读性，背景图上方需要叠加半透明遮罩或局部渐变层。
- 不要使用额外装饰性渐变、光球或营销页式视觉。

## 弹框交互

用户点击 `系统 > 关于佳依创式` 后：

1. main process 触发菜单动作。
2. main process 向当前 BrowserWindow 发送 `about:open` 事件。
3. renderer 中的全局关于弹框组件收到事件后打开。
4. 用户点击右上角关闭按钮、遮罩区域或按 Escape 时关闭弹框。
5. 弹框关闭只改变 renderer UI 状态，不进行任何文件写入。

关于弹框不需要保存、确认、取消等表单动作。底部最多保留一个“关闭”按钮；如果复用公共 `AppModal` 已提供关闭入口，也可以不额外放底部按钮。

## 建议模块拆分

实现时建议沿用现有系统菜单和全局弹框模式：

```text
electron/main/
  menu/
    system-menu.ts
src/
  components/
    system/
      AboutDialog.vue
  api/
    aboutApi.ts
```

职责说明：

- `system-menu.ts`：在 `系统` 菜单下增加 `关于佳依创式`，点击后通知 renderer。
- `aboutApi.ts`：封装 renderer 侧关于弹框打开事件监听，避免 Vue 组件直接依赖裸 IPC 名称。
- `AboutDialog.vue`：展示关于弹框内容、背景图和关闭交互。
- `App.vue`：装配全局关于弹框组件，因为该弹框由顶部菜单触发，不属于某个业务页面。

如果项目已有统一的菜单事件 API，可以直接复用现有封装，不必为了一个事件强行新增过多层。

## IPC 与事件设计

建议新增单向事件：

```text
about:open
```

说明：

- `about:open`：main process 菜单点击后通知 renderer 打开关于弹框。
- 不需要 `about:load`，因为内容写死在 renderer。
- 不需要 `about:save`，因为关于弹框没有持久化行为。

如果 preload 已经有通用菜单事件订阅方法，也可以把 `about:open` 作为其中一个事件名处理，但仍要保持类型声明清晰。

## UI 布局

弹框建议宽度为 `520px` 到 `640px`，高度由内容决定，整体居中。

视觉结构：

- 背景层：使用 `about.jpg` 覆盖弹框内容区。
- 遮罩层：使用深色半透明层保证文字对比度。
- 内容层：软件名称居中，简介和作者信息放在其下方。

文本层级建议：

- 软件名：最大字号，居中，保持稳定宽度，避免换行造成弹框抖动。
- 简介：正常段落宽度，行高略放松，便于阅读。
- 作者和联系方式：信息块形式展示，靠下排列。

移动窗口或小宽度时，弹框宽度应受 `max-width: calc(100vw - 32px)` 约束，避免内容贴边或溢出。

## 与公共组件的关系

如果现有 `AppModal` 能满足以下要求，应优先复用：

- 支持标题或可隐藏标题。
- 支持遮罩点击关闭。
- 支持 Escape 关闭。
- 支持自定义主体内容和宽度。

如果 `AppModal` 的结构无法让背景图覆盖整个关于弹框主体，可以在不破坏其他弹框的前提下增加可选样式入口，例如 `bodyClass` 或 `contentClass`。不要为了关于弹框复制一套通用弹框遮罩和关闭逻辑。

## 错误与降级

关于弹框本身不涉及文件读取，因此不应出现业务错误提示。

资源加载失败时的降级规则：

- 弹框仍然可以打开。
- 使用纯色深色背景作为兜底。
- 软件名称、简介、作者和联系方式必须仍然可读。

## 非目标

第一版不实现：

- 关于信息可编辑。
- 从 JSON、远程接口或系统配置读取关于信息。
- 检查更新。
- 许可证列表。
- 开源依赖清单。
- 版本更新日志。
- 外部链接跳转。
- 写入小说项目目录或系统配置。

## 验证建议

实现完成后至少验证：

1. 点击 `系统 > 关于佳依创式` 可以打开关于弹框。
2. 未打开小说项目时仍然可以打开关于弹框。
3. 弹框中软件名 `佳依创式` 居中展示。
4. 简介、作者 `GPT5.5、刘伟` 和联系方式 `lw18751836671@163.com` 文本正确。
5. 背景图 `src/assets/about.jpg` 能正常显示。
6. 背景图加载失败时文字仍然可读。
7. 点击关闭按钮、遮罩区域和按 Escape 都能关闭弹框。
8. 打开和关闭关于弹框不会修改任何 JSON 文件。
